   the publication rule (CB-3) as one predicate.

`sitemap.xml`, `llms.txt`, `llms-full.txt`) already reads through the one docs repository.

## Risks & open questions
- **Wiring is not unit-tested** (the container is composition only). Recommendation: prove CB-1/CB-2
  at system level in VERIFY by probing the built server (same probe as the "before" capture) rather
  than adding a container test seam — cheaper, and it tests what users actually hit.
- **Where the rule lives.** It is a publishing rule about files, so it sits in the content
  infrastructure next to the file-system adapter; the domain stays file-agnostic (F-1).
  Recommendation: keep it there; BR-11 documents it.
- **Local checkout drift.** The user's main checkout has uncommitted roadmap edits in `container.ts`.
  Recommendation: build on this clean branch; after merge, re-sync the local checkout without
  touching the uncommitted work (reported at ship).
