falls below 8, build stops (R-10).

## Risks & open questions
- **Your checkout has uncommitted roadmap edits in 5 of these files** (`container.ts`,
  `application/index.ts`, `en.ts`, `tr.ts`, `+layout.svelte`). Recommendation: build in a clean
  worktree from `origin/main`, as for 0001, then re-sync your checkout after the merge. The 5
  files get merged by hand. Your roadmap work is never committed by this feature.
- **Merchant emails.** Big brands rarely publish one. Recommendation: expect most cards to use the
  contact page, which is fine under R5. No scraping, and no guessed addresses.
- **The source per merchant.** The scrolls cite only the case-study index. Recommendation: use
  each brand's own case-study page as the source (verified in build), since it is stronger
  evidence than the index.
- **The "Our app" phase.** It comes from the existing `status: "next"` in `path.*.json`, so it
  stays correct as long as you keep updating that field. No new mechanism.
- **Scope check.** About 22 files, the largest feature so far. Recommendation: keep it as one spec
  but commit in the 8 steps above, so review can follow the order.
