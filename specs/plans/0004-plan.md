# Plan 0004 — The header fits a phone

- Spec: `specs/active/0004-mobile-header-fits.md`
- Status: Approved
- Approved by / on: Cemal Karabulaklı, 2026-10-07

## Files to change or add
1. `src/routes/+layout.svelte` — header markup classes only. No new component and no JavaScript.
   - `nav`: add `flex-wrap` and `justify-center`. Use `rounded-2xl` on small screens and
     `sm:rounded-full` from 640 px, so the 1280 px look is unchanged (PB-1).
   - Each nav link gets `whitespace-nowrap`, so its icon and label stay on one line. Today, on a
     phone, the icon wraps above the label.
   - The header's own row layout stays as it is (logo, nav, language switch), so PB-1 and PB-3 hold.
2. `scripts/` — nothing. The header probe is a VERIFY tool in the scratchpad, not part of
   `scripts/check`, because it needs Chrome (`docs/testing.md`, "Outside scripts/check").

No test is added to `scripts/check`. Layout widths can only be measured in a real browser, so the
evidence is the before/after Playwright probe and screenshots (`docs/testing.md`, "Evidence for UI
criteria").

## Ordered steps
1. Branch `feature/0004-mobile-header-fits` in a clean worktree from `origin/main`. Change the
   classes → `fix(layout): header nav wraps on phones instead of widening the page [plan 0004/1]`.
2. `./scripts/check` green. Build, run the header probe and compare with `before.txt`.

## Risks & open questions
- **A wrapped nav could still overflow at 320 px** if any single link plus padding is wider than the
  screen. The widest link is about 120 px ("🧑‍🚀 Traveller" / "Gezgin"), so this is very unlikely.
  The probe checks it at 320 px.
- **Rows that end up uneven,** e.g. 8 links plus RSS alone on a row. `justify-center` keeps it
  tidy. It is cosmetic and is judged on the screenshots in VERIFY.
